- 正式 Edge 为 `jnq-admin-formal`，版本 1，`verify_jwt=true`。服务器每次通过正式 Auth 的 `getUser` 核对当前身份，再检查独立 Editor / Publisher UUID 名单。

## 只读边界

只允许 Session、Spot、地区、slug、关联链接、Note、Guide 和禁用状态的发布信息读取。其他资料不提供泛化 SQL 或浏览器指定字段查询。所有非 GET 操作在服务端鉴权后返回 405，包括新增、编辑、删除、上传与发布。前端的写请求也返回明确的只读拒绝。

Spot 返回管理员使用的 36 字段和地区关联，包含未公开内容。Notes / Guides 通过服务端 Storage authenticated 读取真实最新指针和不可变版本，并在读完后复核指针。禁止退回公开旧 feed。

会话必须具有正式项目 issuer、authenticated role、用户 UUID、非空有效 session_id 和未过期时间。对这些声明的本地解码不授予权限，签名及当前用户/会话仍由正式 Auth 核实。Supabase Auth 的对应实现会查询 session_id，已删除的会话应被拒绝。真实登出后的 Token 重放验收仍需完成。[官方 Auth 实现](https://github.com/supabase/auth/blob/v2.184.0/internal/api/auth.go)

## 异机加密备份准备

现有 PostgreSQL 逻辑备份、SHA-256 与离线恢复回执继续有效，本轮不重新 dump。已发现 X、Y、Z 三个正常挂载的 NAS 共享，实际映射只在用户交付中列出，不将设备路径提交公开仓库。可信度、专属目录及访问权限仍由用户确认，未复制任何备份。

本机已有 Git 随附的 GPG，未安装额外软件。后续流程如下。

1. 用户确认 NAS 上的专属目标目录及可访问账号。在本机 owner-only 私有目录用系统 tar 打包已验收的数据库目录、authority-backup、media-exceptions-backup、静态部署 tar、媒体映射与配置快照，排除构建目录、node_modules、执行器密钥和临时文件。
2. 用户本人运行 GPG 对该备份包做 AES-256 对称加密，密码通过交互式提示输入，不使用数据库密码，不放入命令参数、日志或聊天。保留原始备份，密文使用新的文件名。密码由用户独立保管。
3. 为密文生成 SHA-256。只把密文及其哈希复制到获准 NAS 目录，先以 `.partial` 名称写入，读回密文验证哈希一致后再改为最终名称。
4. 在另一台可信设备，将密文解密到新建的受保护临时目录。逐项核对原有备份 manifest SHA-256，确认 Auth / 角色 / ACL / Storage metadata 和 Note / Guide 指针对象清单完整。
5. 使用已有匹配版本的本机无网络 PostgreSQL 临时实例及原恢复脚本做独立恢复核对。结果写入脱敏回执，清理此次临时实例，绝不向正式项目恢复。

目标目录未确认，因此异机备份保持 PENDING。以上是待执行流程，尚无异机复制或恢复成功结论。

## 部署及回退

使用 `formal-admin-deploy.mjs` 的 `--preflight`、`--edge`、`--pages` / `--verify-pages` 模式，始终要求准确正式项目 ID。复用原管理员界面，只重建这个小型后台包以将登出限定为当前会话；没有重建公开网站。正式 Edge 仅打包读路径和身份校验，三个服务端配置仅为 Origin 与两个已确认 UUID 名单，临时配置文件已清理。没有新建数据库凭据或把执行器密钥交给前端。

第一次 Pages 提交被安装版本 Wrangler 的 `--config` 参数检查拒绝。官方 API 确认部署数为零后，归档原提交回执，改为标准项目目录配置并强制使用 Pages，成功复用同一个 Admin 包。未知结果只允许查询 `--verify-pages`，不能盲目重发。

如果只读后台异常，暂停该独立 Admin 入口或回退此 Edge 版本，保持编辑、上传、发布 OFF。公开站和原始数据库、Storage、R2 无需随该后台回退。本机正式 Publisher 任务继续 Disabled，真正的生产执行动作尚未启用。
